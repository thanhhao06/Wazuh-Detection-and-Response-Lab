# Phát Triển Luật Cảnh Báo: Điều Tra Khởi Tạo Scheduled Task Trái Phép (Persistence - T1053.005)

## 1. Tổng Quan (Overview)
Trong quá trình xây dựng hệ thống phòng thủ, một trong những kỹ thuật mà tôi thường xuyên quan sát thấy các nhóm tấn công (Threat Actors) sử dụng để duy trì quyền truy cập (Persistence) trên hệ thống mục tiêu là tạo Scheduled Task. Kỹ thuật này tương ứng với MITRE ATT&CK T1053.005. Trong bài viết này, tôi sẽ trình bày cách thức xây dựng cơ chế phát hiện (Detection Engineering) đối với hành vi tạo Scheduled Task trái phép bằng công cụ `schtasks.exe`, cụ thể là việc lập lịch chạy một tệp tin độc hại như `reverse_shell.exe`.

## 2. Vấn Đề (The Problem)
Sau khi khai thác thành công và có được chỗ đứng trên hệ thống (Initial Access), tôi nhận thấy kẻ tấn công thường sẽ tìm cách duy trì quyền truy cập. Một cách phổ biến là tạo ra một tác vụ theo lịch trình (Scheduled Task) để thực thi mã độc hoặc payload định kỳ hoặc mỗi khi khởi động máy. 
Câu lệnh mà tôi thường thấy chúng sử dụng có dạng như sau:
`schtasks.exe /create /tn "Updater" /tr "C:\Users\Public\reverse_shell.exe" /sc onlogon /ru System`
Hành vi này rất nguy hiểm và tôi cần phát hiện kịp thời để ngăn chặn kẻ tấn công thiết lập Persistence.

## 3. Logic Phát Hiện (Detection Logic)
Để phát hiện kỹ thuật này, tôi tập trung vào hai nguồn log chính:
1.  **Sysmon Event ID 1 (Process Creation):** Giám sát sự kiện tạo tiến trình. Tôi sẽ tìm kiếm tiến trình `schtasks.exe` đi kèm với các tham số dòng lệnh (Command Line) chứa từ khóa `/create`.
2.  **Windows Security Event ID 4698 (A scheduled task was created):** Đây là Event ID mặc định của Windows sinh ra khi có một Scheduled Task mới được tạo. Trong chi tiết sự kiện này, tôi sẽ kiểm tra phần Actions để xem đường dẫn thực thi có chứa các thư mục đáng ngờ hay tệp tin lạ không.

## 4. Triển Khai Luật Wazuh (Wazuh Rule Implementation)
Dưới đây là các luật tôi đã viết và thêm vào tệp `local_rules.xml` của Wazuh để phát hiện cả hai trường hợp trên:

```xml
<group name="windows, sysmon, scheduled_task,">
  <rule id="100050" level="10">
    <if_group>windows</if_group>
    <match>schtasks.exe</match>
    <match>/create</match>
    <description>SOC Lab - Suspicious Scheduled Task created via schtasks.exe</description>
    <mitre>
      <id>T1053.005</id>
    </mitre>
  </rule>

  <rule id="100051" level="10">
    <if_group>windows</if_group>
    <field name="win.system.eventID">^4698$|^4702$</field>
    <match>WindowsUpdate_Backup</match>
    <description>SOC Lab - Suspicious Scheduled Task created (Event 4698)</description>
    <mitre>
      <id>T1053.005</id>
    </mitre>
  </rule>
</group>
```

## 5. Cảnh Báo Giả & Tinh Chỉnh (False Positives/Tuning)
Mặc dù logic trên rất hiệu quả, nhưng trong môi trường doanh nghiệp thực tế, tôi gặp phải khá nhiều cảnh báo giả (False Positives). Các phần mềm hợp lệ như trình duyệt web, phần mềm diệt virus hoặc các công cụ quản trị (ví dụ: SCCM) thường xuyên tạo Scheduled Task.
Để giảm nhiễu, tôi thường thực hiện các bước tinh chỉnh (Tuning) sau:
*   **Loại trừ theo thư mục hợp lệ:** Nếu Task thực thi file từ `C:\Program Files\` hoặc `C:\Windows\System32\` (và file đã được xác minh chữ ký số hợp lệ), tôi có thể tạo luật loại trừ (whitelist).
*   **Theo dõi Command Line cụ thể:** Tập trung cảnh báo vào các Scheduled Task chạy script (`cmd.exe`, `powershell.exe`) hoặc gọi các file từ thư mục tạm/thư mục người dùng (`C:\Users\Public\`, `%TEMP%`).

Ví dụ về luật tinh chỉnh loại trừ do tôi thiết lập:
```xml
  <rule id="100052" level="0">
    <if_sid>100050</if_sid>
    <field name="win.eventdata.commandLine" type="pcre2">(?i)C:\\Program Files\\Google\\Chrome\\Updater</field>
    <description>SOC Lab - False positive bypass for Google Chrome Updater</description>
  </rule>
```

## 6. Kết Luận (Conclusion)
Thông qua việc tôi giám sát chặt chẽ hành vi tạo Scheduled Task bằng `schtasks.exe` qua Sysmon (Event ID 1) và Windows Security Log (Event ID 4698), tôi có thể phát hiện sớm các kỹ thuật Persistence (T1053.005). Việc kết hợp giữa cảnh báo và tinh chỉnh loại trừ các phần mềm hợp lệ giúp tôi tăng cường độ chính xác cho hệ thống giám sát an ninh (SOC) của tổ chức.
