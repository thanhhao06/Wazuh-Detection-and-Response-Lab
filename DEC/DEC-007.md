# DET-007 — Kỹ Thuật Phát Hiện Trích Xuất Bộ Nhớ LSASS (T1003.001)

## 1. Tổng Quan Kiến Trúc Phát Hiện (Detection Overview)
*   **Case ID:** DET-007
*   **Mục tiêu (Objective):** Phát hiện, cảnh báo và ngăn chặn hành vi đọc hoặc kết xuất (dump) bộ nhớ của tiến trình `lsass.exe` nhằm đánh cắp thông tin đăng nhập (Credential Dumping) trên môi trường Windows.
*   **Log Nguồn:** Sysmon Event ID 10 (Process Access), Windows Security Event 4656 (A handle to an object was requested), Windows Security Event 4663 (An attempt was made to access an object).
*   **Tác giả / Ngày cập nhật:** Đội ngũ Detection Engineering / 2026-08-26
*   **MITRE ATT&CK:** 
    *   Tactic: Credential Access (TA0006)
    *   Technique: OS Credential Dumping (T1003)
    *   Sub-technique: LSASS Memory (T1003.001)

## 2. Bối Cảnh Mối Đe Dọa (Threat Context)
Tiến trình Local Security Authority Subsystem Service (`lsass.exe`) là thành phần cốt lõi của Windows chịu trách nhiệm thực thi các chính sách an ninh, quản lý quá trình đăng nhập và lưu trữ các thông tin đăng nhập, token xác thực (NTLM hashes, Kerberos tickets) trong bộ nhớ. Kẻ tấn công thường sử dụng kỹ thuật trích xuất bộ nhớ (Memory Dumping) đối với `lsass.exe` để trích xuất các thông tin này dưới dạng bản rõ (cleartext) hoặc hash nhằm thực hiện các kỹ thuật như Pass-the-Hash (PtH) hay Pass-the-Ticket (PtT), cho phép leo thang đặc quyền và di chuyển ngang (lateral movement) trong mạng doanh nghiệp.

Các công cụ phổ biến được sử dụng:
*   Mimikatz (sử dụng module `sekurlsa::logonpasswords`)
*   ProcDump (Sysinternals) với cú pháp `procdump.exe -accepteula -ma lsass.exe lsass.dmp`
*   Task Manager (Create dump file)
*   Rundll32 (thông qua `comsvcs.dll`, ví dụ: `rundll32.exe C:\windows\System32\comsvcs.dll, MiniDump 624 lsass.dmp full`)

## 3. Phân Tích Logic Dữ Liệu (Telemetry Logic)
Khác với Sysmon Event ID 1 (Process Creation - ghi nhận việc tạo tiến trình), **Sysmon Event ID 10** ghi nhận hành vi một tiến trình đang hoạt động (Source Image) cố gắng mở handle, đọc, hoặc ghi vào bộ nhớ của một tiến trình khác (Target Image). Đối với kịch bản này, `lsass.exe` chính là Target Image.

**Các trường dữ liệu pháp y cốt lõi (Forensic Fields):**
*   **`win.eventdata.targetImage`:** Bắt buộc là `C:\Windows\System32\lsass.exe`. SIEM cần giám sát chặt chẽ mọi handle request tới process này.
*   **`win.eventdata.sourceImage`:** Tiến trình thực hiện hành vi truy cập (Ví dụ: `cmd.exe`, `powershell.exe`, hoặc tiến trình tùy chỉnh của malware). Đặc biệt lưu ý các công cụ hợp lệ nhưng bị lạm dụng (LotL) như `rundll32.exe`, `taskmgr.exe`, `procdump.exe`, `sqldumper.exe`.
*   **`win.eventdata.grantedAccess`:** Cờ định danh mức độ quyền hạn được yêu cầu và cấp phát. Các giá trị cảnh báo mức độ rủi ro cao:
    *   `0x1FFFFF`: (Full Access / PROCESS_ALL_ACCESS) - Quyền truy cập toàn diện.
    *   `0x1410`: (PROCESS_QUERY_INFORMATION | PROCESS_VM_READ) - Quyền đọc bộ nhớ của process.
    *   `0x1010`: Quyền đọc bộ nhớ thường được thấy từ Task Manager hoặc các công cụ native khác.
    *   `0x1438`: Quyền truy cập thường được Mimikatz yêu cầu.
*   **`win.eventdata.callTrace`:** Chuỗi gọi hàm (Call Stack). Rất hữu ích để nhận diện các module DLL đáng ngờ (ví dụ: `dbghelp.dll`, `dbgcore.dll` thường được dùng để tạo minidump) được load bởi `SourceImage`.

### 4.2. Sigma Rule Example
```yaml
title: LSASS Memory Dump Detection
id: 9a22495b-0136-4c75-b6d3-2e0618057c7c
status: experimental
description: Detects process access to LSASS which indicates memory dumping activity.
logsource:
    category: process_access
    product: windows
detection:
    selection_target:
        TargetImage|endswith: '\lsass.exe'
    selection_access:
        GrantedAccess:
            - '0x1fffff'
            - '0x1410'
            - '0x143a'
            - '0x1438'
            - '0x1010'
    filter_system:
        SourceImage|startswith: 'C:\Windows\System32\'
        SourceImage|endswith: 
            - '\svchost.exe'
            - '\csrss.exe'
            - '\services.exe'
            - '\wininit.exe'
            - '\smss.exe'
    filter_av:
        SourceImage|contains: 
            - 'C:\ProgramData\Microsoft\Windows Defender\Platform\'
            - '\MsMpEng.exe'
    condition: selection_target and selection_access and not (filter_system or filter_av)
level: high
tags:
    - attack.credential_access
    - attack.t1003.001
```

## 5. Xử Lý Nhiễu (False Positive Tuning / Whitelisting)
Tiến trình `lsass.exe` là một cấu phần trọng yếu, liên tục bị truy cập bởi các phần mềm hợp lệ của hệ điều hành và các giải pháp bảo mật trong môi trường doanh nghiệp. Việc xử lý nhiễu (tuning) phải cực kỳ khắt khe để tránh bỏ sót các hành vi tinh vi.

*   **Hành vi hợp lệ (Expected Behavior):** 
    *   Các thành phần nội tại của Windows: `svchost.exe`, `csrss.exe`, `wininit.exe`, `services.exe`.
    *   Tiến trình của EDR / Antivirus / Vulnerability Scanners: `MsMpEng.exe` (Windows Defender), `TaniumClient.exe`, `qualysagent.exe`, các tác nhân CrowdStrike, SentinelOne.
*   **Giải pháp Tinh chỉnh Tối ưu:** 
    1.  **Dựa trên Chữ ký số (Valid Signature):** Whitelist dựa trên `Signature` hoặc `SignatureStatus` của `SourceImage`. Đảm bảo file được ký bởi Microsoft hoặc nhà cung cấp EDR, và chứng chỉ hợp lệ.
    2.  **Dựa trên Mã băm (Hash):** Whitelist các mã hash cụ thể của phần mềm diệt virus đã được phê duyệt trong mạng nội bộ.
    3.  **Tuyệt đối KHÔNG Whitelist thuần túy theo tên tệp (`SourceImage`):** Kẻ tấn công có thể dễ dàng sao chép mã độc, đổi tên thành `svchost.exe` hoặc lưu trong các thư mục hợp lệ giả mạo (ví dụ: `C:\Windows\Temp\svchost.exe`).
    4.  **Tuning theo thư mục (Path-based tuning):** Nếu phải kết hợp, hãy kiểm tra đường dẫn tuyệt đối (VD: `C:\Windows\System32\svchost.exe`) kèm điều kiện hệ thống.

## 6. Kế Hoạch Ứng Phó Sự Cố (Incident Response Playbook)
Khi cảnh báo DET-007 được kích hoạt, tôi cần thực hiện các bước sau:
1.  **Xác minh nguồn gốc (Triage):**
    *   Kiểm tra `SourceImage` là gì? Có hợp lệ hay không? Nằm ở thư mục nào?
    *   Kiểm tra chữ ký số (Signature) và mã băm (Hash) của `SourceImage` trên VirusTotal.
2.  **Điều tra mở rộng (Scoping):**
    *   Trước thời điểm cảnh báo 10 phút, User/Endpoint này có tải file gì lạ không? (Event ID 11 - File Create, Proxy/Web logs).
    *   Xem xét `CallTrace` có chứa các API đáng ngờ như `MiniDumpWriteDump`.
    *   Có sự xuất hiện của các file `.dmp` mới sinh ra ở các thư mục như `%TEMP%`, `C:\PerfLogs`, v.v. (Event ID 11) không?
3.  **Ngăn chặn và Khắc phục (Containment & Eradication):**
    *   Nếu xác định là tấn công thật (True Positive): Cô lập ngay lập tức máy chủ/máy trạm (Network Isolation) qua EDR.
    *   Thu thập bộ nhớ hiện tại để phân tích pháp y (Memory Forensics) nếu cần.
    *   Tiến hành reset password cho tài khoản đang bị nghi ngờ lộ lọt, đặc biệt là tài khoản Domain Admin.
    *   Xóa bỏ các tệp tin độc hại, vô hiệu hóa các Scheduled Task/Services liên quan đến mã độc.
